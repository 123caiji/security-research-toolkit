# SKILL: 蜜罐反制与溯源攻击

## 1. 反制的大致流程

```
蜜罐部署 → 木马投放 → 上线监控 → 溯源反制 → 攻击队定位
```

## 2. 蜜罐部署

### 部署注意事项

1. **提前报备**：部署的蜜罐需提前向裁判报备，避免后续扯皮
2. **单独隔离**：蜜罐需单独隔离，防止横向扩散
3. **高仿真**：蜜罐不能太假，要给攻击者一种靠自己努力获取成果的假象
4. **避免云蜜罐**：直接使用厂商云蜜罐特征明显，容易被标记为蜜罐

### 环境选择

**推荐使用真实漏洞环境**：
- 致远OA环境（保留nday漏洞）
- 其他常见企业应用

**镜像导入**：
```
云服务器镜像导入需安装驱动：
https://cloud.tencent.com/document/product/213/17815
```

### 域名配置

```
域名命名以常见字典字符为主：demo、crm、test等
确保能被子域名扫描器识别到

可通过WAF自定义重定向页面至蜜罐地址，加快Fofa、Hunter等测绘平台收录速度
```

## 4. 溯源反制

### 常规溯源

**IP去重与指纹识别**：
```bash
# 使用ehole进行指纹识别
ehole -d target_ip
```

**案例**：
```
根据IP进行端口扫描发现搭建了灯塔系统
通过态势感知平台发现扫描行为
去微步进行IP查询，发现IP绑定了域名
通过WHOIS查询获取攻击者姓名和邮箱
```

### 反制攻击队成员

**案例1：浏览器历史记录**
```
攻击者浏览器历史记录中包含手机号
百度搜索确认归属地与比赛不匹配
通过手机号反查个人信息，获取姓名和学校
通过内部通讯录确认攻击队队员身份
```

**案例2：Cookie/Token泄露**
```
从python脚本文件找到ICP备案查询的cookie和token
Burp替换cookie后获取攻击者百度ID
搜索定位真实姓名和单位
通过CISP-PTE考试信息进一步确认身份
```

**案例3：微信钓鱼反制**
```
攻击队发送微信钓鱼
使用热点和虚拟机模拟个人终端环境
点击攻击队的木马程序
在桌面上放置反钓鱼木马文件（xx蓝方信息表）
使用lnk文件+加密rar压缩包
攻击队解压后点击lnk文件成功上线
```

## 6. 实战建议

### 操作流程

1. **部署蜜罐**：选择高仿真环境，配置域名
2. **投放木马**：制作免杀马，选择合适诱饵
3. **设置监控**：配置上线告警，及时发现攻击
4. **记录证据**：边录屏边操作，避免遗漏重要内容
5. **溯源分析**：分析攻击者信息，定位身份
6. **提交证据**：交叉举证，确认攻击者身份

### 注意事项

1. **法律合规**：所有操作需在合法授权范围内进行
2. **证据保全**：保留所有操作记录和证据
3. **安全隔离**：蜜罐需与真实系统隔离
4. **及时上报**：发现攻击及时上报相关部门

### 常见问题

**Q1：如何避免蜜罐被识别？**
```
- 使用真实漏洞环境，而非云蜜罐
- 配置高仿真服务和数据
- 避免明显的蜜罐特征
```

**Q2：如何提高木马点击率？**
```
- 使用有吸引力的诱饵文件
- 配合文档指导增加可信度
- 选择合适的投放时机
```

**Q3：如何保护自身安全？**
```
- 使用隔离环境操作
- 避免使用个人设备
- 及时清理痕迹
```

## 8. [补充推演] 蜜罐类型矩阵

### 按交互等级分类

| 类型 | 交互等级 | 代表工具 | 部署复杂度 | 情报价值 | 被识别风险 |
|---|---|---|---|---|---|
| 低交互蜜罐 | 低 | Honeyd, Cowrie | 低 | 低 | 高 |
| 中交互蜜罐 | 中 | Dionaea, Kippo | 中 | 中 | 中 |
| 高交互蜜罐 | 高 | 真实漏洞环境 | 高 | 高 | 低 |
| 蜜网 | 混合 | T-Pot, HFish | 高 | 高 | 低 |

### 按部署位置分类

| 类型 | 部署位置 | 目标 | 常用工具 |
|---|---|---|---|
| Web蜜罐 | DMZ/外网 | Web攻击者 | OPENCANARY, Wordpot |
| 服务蜜罐 | 内网/外网 | 服务扫描者 | Cowrie(SSH), Dionaea(SMB) |
| 数据库蜜罐 | 内网 | 数据库探测者 | MySQL蜜罐, Redis蜜罐 |
| 文件蜜罐 | 内网 | 文件窃取者 | Honeyfiles, Canarytokens |
| 域内蜜罐 | 域环境 | 域攻击者 | ADSecurity蜜罐, HoneyUser |

### 常见蜜罐工具对比

**HFish（国产）**：
```
- 支持多种协议蜜罐（SSH/FTP/Redis/MySQL等）
- Web管理界面，集中监控
- 支持多节点部署
- 适合HW期间大规模部署
```

**T-Pot（综合平台）**：
```
- 集成20+种蜜罐
- Docker容器化部署
- ELK集成，自动分析
- 适合学习和研究使用
```

**Canarytokens（轻量级）**：
```
- 在线生成蜜罐标记（文件/URL/DNS等）
- 无需部署服务器
- 适合快速部署和检测
- URL: https://canarytools.org/
```

**Cowrie（SSH/Telnet蜜罐）**：
```
- 模拟SSH和Telnet服务
- 记录攻击者命令和上传文件
- 支持中等交互
- 适合收集SSH爆破数据
```

**Dionaea（多协议蜜罐）**：
```
- 支持SMB/FTP/HTTP/TFTP/MQTT等
- 捕获漏洞利用payload
- 适合捕获漏洞利用尝试
```

## 9. [补充推演] 蜜罐检测对抗体系

### 攻击者识别蜜罐的常见手段

| 检测方法 | 检测原理 | 对抗手段 |
|---|---|---|
| TTL异常检测 | 蜜罐响应TTL可能异常 | 使用真实系统作为蜜罐 |
| MAC地址检测 | 虚拟机MAC地址前缀 | 使用真实物理机 |
| 端口指纹检测 | 蜜罐端口行为与真实服务不一致 | 使用高交互蜜罐 |
| 响应延迟检测 | 蜜罐响应延迟可能异常 | 优化蜜罐性能 |
| 系统信息检测 | 蜜罐系统信息不完整 | 使用真实系统镜像 |
| 流量模式检测 | 蜜罐流量模式异常 | 模拟正常业务流量 |
| 文件系统检测 | 蜜罐文件系统过于简单 | 部署真实业务数据 |
| 用户行为检测 | 蜜罐无真实用户活动 | 模拟用户登录活动 |

### 蜜罐反检测技巧

```
1. 使用真实操作系统作为蜜罐
2. 部署真实业务应用和数据
3. 配置合理的系统信息（MAC/系统版本/补丁）
4. 模拟正常用户活动（定时登录/文件操作）
5. 保持端口行为与真实服务一致
6. 配置合理的网络拓扑
7. 避免使用已知蜜罐工具的特征签名
8. 使用CDN和域名增加可信度
```

### HoneyUser（蜜罐用户）部署

```
在AD域中创建虚假的特权用户，但该账户没有任何实际权限
当攻击者尝试使用该账户登录时触发告警

部署步骤：
1. 创建虚假域管理员账户（如"backup_admin"）
2. 将账户加入敏感组（但无实际权限）
3. 配置该账户的登录告警
4. 监控该账户的所有活动

检测场景：
- 攻击者通过BloodHound发现该用户为域管
- 攻击者尝试Kerberoasting攻击该用户
- 攻击者尝试使用该用户凭据登录
→ 任何对HoneyUser的操作都表示域内有攻击者
```

### HoneyToken（蜜罐文件）部署

```
1. 创建虚假的密码本/配置文件/SSH密钥
2. 在文件中植入Canarytokens
3. 将文件放置在攻击者容易发现的位置
4. 当文件被访问/复制时触发告警

部署位置建议：
- 桌面（passwords.txt）
- 共享文件夹（vpn_config.txt）
- 代码仓库（.env文件）
- 数据库（虚假的凭据表）
```

## 10. [补充推演] 蜜网架构设计

### 蜜网架构

```
互联网 → 防火墙 → 蜜网隔离区（DMZ）
                    ├── Web蜜罐（高交互）
                    ├── SSH蜜罐（Cowrie）
                    ├── 数据库蜜罐
                    ├── 文件蜜罐
                    └── 蜜网网关（日志收集/告警）

内网 → 蜜罐节点
        ├── HoneyUser（域内蜜罐用户）
        ├── HoneyToken（蜜罐文件）
        └── 内网服务蜜罐（模拟内部服务）
```

### 蜜网网关功能

```
1. 数据捕获：记录所有进出蜜网的流量
2. 数据控制：限制蜜罐对外发起连接的数量
3. 日志集中：汇总所有蜜罐日志
4. 告警通知：实时通知安全团队
5. 攻击分析：自动化分析攻击行为
```

### 部署架构

**分布式蜜罐架构**：
```
管理节点 → 中央控制台
  ├── 外网蜜罐节点（部署在DMZ）
  ├── 内网蜜罐节点（部署在关键网段）
  ├── 域内蜜罐（部署在AD环境）
  └── 云蜜罐（部署在云环境）

数据流：蜜罐节点 → 日志收集器 → SIEM → 告警 → 安全团队
```

### 自动化分析管道

```bash
# 1. IP情报自动查询
for ip in $(cat attacker_ips.txt); do
    curl -s "https://api.threatbook.cn/v3/scene/ip_reputation?api_key=$KEY&ip=$ip" >> ip_intel.json
done

# 2. 恶意文件自动分析
# 上传到VirusTotal
for file in /malware_samples/*; do
    curl -X POST "https://www.virustotal.com/api/v3/files" \
        -H "x-apikey: $VT_KEY" \
        -F "file=@$file"
done

# 3. 自动提取攻击者IP的开放端口
for ip in $(cat attacker_ips.txt); do
    nmap -sV -p 1-1000 $ip -oX "scan_$ip.xml"
done

# 4. 自动指纹识别
ehole -l attacker_ips.txt -o fingerprints.txt
```
